## 一、核心概念與資料架構

### 1.1 車輛主檔（Vehicle Master）

系統中每一輛車，從進入供應鏈的第一刻起，就必須擁有唯一的車輛主檔記錄。
這是整個模組的骨幹，所有流程的起點與終點都與此主檔連動。

#### 車輛主檔欄位定義

| 欄位名稱 | 欄位代號 | 型別 | 說明 |
|---------|---------|------|------|
| 系統車輛ID | `vehicle_id` | UUID | 系統自動產生，唯一識別碼 |
| VIN碼（車架號） | `vin` | String(17) | 國際標準17碼，必填，唯一 |
| 生產號 | `serial_no` | String | 原廠生產序號 |
| 車輛類型 | `vehicle_type` | Enum | `NEW`（新車）/ `USED`（中古車） |
| 品牌 | `brand` | String | 例：Indian |
| 車系 | `series` | String | 例：Scout、Challenger |
| 車型 | `model` | String | 例：Scout Bobber |
| 年份 | `model_year` | Integer | 例：2026 |
| 外觀顏色 | `color_ext` | String | |
| 顏色代碼 | `color_code` | String | 原廠色碼 |
| 車輛狀態 | `vehicle_status` | Enum | 詳見 1.2 狀態機 |
| 所有權歸屬 | `ownership` | Enum | `IMPORTER`（海德生）/ `DEALER`（經銷商）/ `SOLD`（已售） |
| 實體位置 | `location_warehouse_id` | FK | 指向倉庫主檔，可為海德生倉或經銷商外部庫位 |
| 採購成本（未稅） | `purchase_cost` | Decimal | 向原廠採購的發票金額 |
| 關稅 | `customs_duty` | Decimal | 進口關稅，由批次分攤計算 |
| 運費分攤 | `freight_cost` | Decimal | 進口運費，由批次分攤計算 |
| 保險費分攤 | `insurance_cost` | Decimal | 進口保險費，由批次分攤計算 |
| PDI工時費用 | `pdi_labor_cost` | Decimal | 由PDI工單完成後自動寫入 |
| PDI零件費用 | `pdi_parts_cost` | Decimal | 由PDI工單完成後自動寫入 |
| 整備費用（中古） | `recon_cost` | Decimal | 僅中古車適用，整備工單費用合計 |
| 調撥運輸費用 | `transfer_freight_cost` | Decimal | 車輛跨倉調撥時產生的運費（選擇計入整車成本時才有值，否則為0） |
| 整車成本合計 | `total_cost` | Decimal | 自動計算：採購+關稅+運費+保險+PDI費用（+整備費用）（+調撥運費，如計入成本） |
| 標準售價（MSRP） | `msrp` | Decimal | 原廠建議售價 |
| 收購價格（中古） | `acquisition_price` | Decimal | 僅中古車：海德生收購價格 |
| 到港日期 | `arrival_date` | Date | |
| 入庫日期 | `stock_in_date` | Date | PDI完成後確認入庫的日期 |
| 在庫天數 | `days_in_stock` | Integer | 系統自動計算（今日 - 入庫日期） |
| 採購單號 | `purchase_order_id` | FK | 關聯整車採購單 |
| 批次號 | `batch_id` | FK | 關聯進口批次（用於費用分攤） |
| PDI工單號 | `pdi_workorder_id` | FK | 關聯售後PDI工單 |
| 中古車來源類型 | `used_source_type` | Enum | `TRADE_IN`（置換）/ `DIRECT_BUY`（直接收購）/ `REPO`（回收） |
| 置換訂單號 | `trade_in_order_id` | FK | 僅置換車輛：關聯銷售訂單 |
| CPO等級 | `cpo_grade` | Enum | `CPO`/ `DPO`/ `CO`/ `NULL` |
| 建立時間 | `created_at` | DateTime | |
| 最後更新時間 | `updated_at` | DateTime | |

### 1.2 車輛狀態機（Vehicle Status Flow）

車輛從進入系統到售出，狀態必須依照以下流程單向推進，**不可逆退**（除非有主管授權的狀態更正申請）。

```
新車流程：
[在途 IN_TRANSIT]
    ↓ 到港確認（逐台掃VIN）
[待PDI PENDING_PDI]
    ↓ PDI工單建立 → 技師執行 → PDI完成核准
[在庫可售 AVAILABLE]
    ↓ 業務建立訂單並鎖定車輛
[已保留 RESERVED]
    ↓ 訂單成交，交車確認
[已售 SOLD]

中古車流程：
[收購評估 EVALUATION]（置換/直購）
    ↓ 收購決策確認
[待整備 PENDING_RECON]
    ↓ 整備工單建立 → 技師執行 → 整備完成核准
[在庫可售 AVAILABLE]
    ↓ 後續流程同新車
[已保留 RESERVED]
    ↓
[已售 SOLD]

特殊狀態：
[寄倉 CONSIGNMENT] — 所有權在海德生，實體在經銷商場地
[調撥中 IN_TRANSIT_TRANSFER] — 跨倉庫調撥進行中
[下架 INACTIVE] — 停止銷售（損壞/召回/其他）
```

### 1.3 整車成本計算公式

**新車整車成本 = 採購成本 + 關稅 + 運費分攤 + 保險費分攤 + PDI工時費用 + PDI零件費用 + 調撥運費（若選擇計入成本）**

**中古車整車成本 = 收購價格 + 整備工時費用 + 整備零件費用 + 其他整備項目費用 + 調撥運費（若選擇計入成本）**

> ⚠️ **中古車調撥的特殊考量**
> 中古車可能在「待整備」或「可售」兩個階段發生調撥，兩種時機的費用影響不同，詳見第五節 5.6。

> ⚠️ **重要：PDI費用不得歸入客戶應收帳款**
> PDI工單的費用歸屬為「整車成本轉入」，付款性質代碼為 `PD-IN`（內部結算：銷售部門→售後部門）。
> 技師執行PDI的工資與零件成本由售後部門認列，費用由銷售部門的該台車輛成本吸收。
> 財務上的處理：借：整車在庫成本（資產科目）/ 貸：售後部門服務收入（內部）

### 2.2 到港確認（INV02）

#### 頁面：`INV02_到港確認.html`

**功能說明：**
車輛實際到港後，倉管人員逐台掃描VIN碼確認到貨，並核對與採購單一致。

**頁面結構：**
```
[搜尋列] 輸入採購單號 → 帶出待確認清單
[到港確認列表] 顯示本批次所有車輛
[逐筆確認區] 掃描或手動輸入VIN
```

**確認作業欄位（每台）：**

| 欄位 | 說明 |
|------|------|
| VIN碼 | 掃描或手動輸入，系統比對採購單 |
| 生產號 | |
| 實際到港日期 | 日期選擇器 |
| 外觀狀態 | 選擇：`完好` / `輕微損傷` / `重大損傷` |
| 損傷說明 | 如有損傷必填 |
| 損傷照片 | 上傳（至少1張，損傷時必填） |
| 實際收貨倉庫 | 確認或修改（可能與採購單倉庫不同） |

**確認後系統行為（關鍵）：**

> ⚠️ **此步驟完成後系統必須自動執行以下動作：**

1. **車輛主檔狀態從 `IN_TRANSIT` 更新為 `PENDING_PDI`**
2. **自動建立 PDI 工單**（詳見第三節）
3. 到港日期寫入車輛主檔 `arrival_date`
4. 觸發通知：發送給售後主管「新車到港，PDI工單已建立，請分派技師」
5. 如有損傷：額外觸發「損傷通知」發送給採購人員，並在車輛主檔標記 `damage_flag = true`

## 三、PDI工單觸發機制（核心）

### 3.1 觸發條件

PDI工單在以下兩種情況自動觸發，**不需要人工手動建立**：

| 觸發情境 | 觸發時機 | 工單前綴碼 |
|---------|---------|-----------|
| 新車到港確認完成 | INV02 逐台確認後立即 | `PD-IN` |
| 中古車收購決策確認 | RS06 收購確認 / 外購收購確認後立即 | `PD-UC` |

### 3.2 PDI工單自動建立規格

系統應在觸發條件成立後，**立即在售後工單資料庫建立一筆新工單**，欄位如下：

| 工單欄位 | 值 | 說明 |
|---------|---|------|
| 工單號 | `PD-IN-{YYYYMMDD}-{序號}` | 系統自動產生 |
| 業務類型 | `PD`（PDI整備） | |
| 付款性質 | `IN`（內部結算） | **不可改為客付或保固** |
| 付款說明 | `整車成本轉入 — 銷售部門負擔` | |
| 車輛VIN | 關聯車輛主檔 | |
| 車型描述 | 自動帶入 | |
| 里程數 | `0` | 新車固定為0 |
| 接車日期 | 到港確認日期 | |
| 預計完工日 | 接車日期 + 1個工作日 | 可由技師調整 |
| 工單狀態 | `PENDING`（待分派） | |
| SA人員 | 系統自動指派：售後主管 | 需人工再分派給技師 |
| 客戶欄位 | `[內部] 海德生貿易` | 使用內部虛擬客戶帳號 |
| 費用歸屬 | `VEHICLE_COST` | 標記費用計入整車成本 |
| 關聯車輛ID | 車輛主檔 `vehicle_id` | |
| checklist類型 | `PDI_NEW`（新車）/ `PDI_USED`（中古） | 決定顯示哪套checklist |

### 3.3 PDI工單執行頁面

#### 頁面：`SA_PDI_工單執行.html`

此頁面由售後技師在工單列表中開啟，執行PDI檢查。

**頁面結構：**
```
[工單資訊列] 工單號 | 車型 | VIN | 接車日期
[進度條] 已完成 N/29 項
[Tab 1] PDI 檢查清單（29項 — 新車 / 或中古整備清單）
[Tab 2] 零件與工時記錄
[Tab 3] 費用彙總（唯讀，顯示目前費用小計）
[底部] 技師簽名 | 主管核准 | 完成PDI
```

**PDI完成後系統行為（關鍵）：**

> ⚠️ **技師完成並主管核准後，系統必須執行以下動作：**

1. **工單狀態更新為 `CLOSED`**
2. **讀取此工單的工時費用與零件費用合計**
3. **自動寫回車輛主檔：**
   - `pdi_labor_cost` = 工單工時費用合計
   - `pdi_parts_cost` = 工單零件費用合計
   - `total_cost` = 重新計算（原成本 + PDI費用）
4. **車輛主檔狀態從 `PENDING_PDI` 更新為 `AVAILABLE`**
5. **RS03A（新車）或RS03B（中古車）看板即時反映此台車狀態變更**
6. 觸發通知：發送給業務主管「VIN：XXXXXX 已完成PDI，現可銷售」

### 3.4 PDI費用科目對照（財務）

| 費用項目 | 借方科目 | 貸方科目 |
|---------|---------|---------|
| PDI工時費 | 整車在庫成本（流動資產） | 售後部門內部服務收入 |
| PDI零件費 | 整車在庫成本（流動資產） | 零件庫存（流動資產） |

> 此處理方式確保：
> - 整車在庫成本真實反映「可售前的所有投入」
> - 售後部門的服務收入有內部帳務紀錄
> - 車輛售出時的毛利計算基準正確（售價 − 整車成本合計）

### 4.2 車輛鎖定 / 解鎖

**功能說明：**
業務人員為客戶配車時，可鎖定特定車輛，防止其他業務同時配給別的客戶。

**鎖定狀態：**
- `未鎖定`：任何業務可配車
- `銷售鎖定`：已被業務鎖定，連結特定訂單
- `主管鎖定`：由主管手動鎖定（例：展示車、媒體試乘車）

**操作：**
- 鎖定：在車輛詳情頁點擊「鎖定」，選擇訂單號或填寫鎖定原因
- 解鎖：需為原鎖定人或主管權限

### 4.3 車輛調撥（海德生↔經銷商）

#### 頁面：`INV04_車輛調撥.html`

**情境A：海德生主倉 → 經銷商寄倉**
- 所有權不變（仍為海德生）
- 實體位置更新
- 狀態不變（仍可在海德生公開庫存顯示）
- 建立「寄倉記錄」，記錄放置經銷商的起始日期

**情境B：海德生庫存 → 經銷商採購（所有權轉移）**
- 經銷商發起「整車採購申請」
- 海德生審核核准
- 審核通過後：所有權從 `IMPORTER` 更新為 `DEALER`
- 財務建立應收帳款（對應經銷商）

**情境C：經銷商A → 經銷商B（調撥）**
- 需海德生核准
- 所有權視情況（如已售給A則需A→B二次交易）
- 車輛狀態期間標記 `IN_TRANSIT_TRANSFER`
- **調撥運輸費用處理（必須明確）：**

  調撥過程中會產生實際運輸費用（拖車/貨運），此費用的歸屬需在調撥申請時明確選擇：

  | 費用承擔方式 | 代碼 | 說明 | 典型情境 |
  |------------|------|------|---------|
  | 由申請方（經銷商B）全額承擔 | `FREIGHT-B` | 費用計入B的應付帳款 | 最常見，B主動要車 |
  | 由調出方（經銷商A）全額承擔 | `FREIGHT-A` | 費用計入A的應付帳款 | A庫存積壓主動推出 |
  | 海德生承擔（全額） | `FREIGHT-IMP` | 費用計入海德生營業費用 | 海德生主動調配庫存結構 |
  | 雙方各半 | `FREIGHT-SPLIT` | 各計50%應付帳款 | 協議調撥 |
  | 計入車輛成本 | `FREIGHT-VEHICLE` | 費用加入車輛 `total_cost` | 車輛尚未定價，成本需重算 |

  > ⚠️ **重要：若選擇 `FREIGHT-VEHICLE`（計入車輛成本）**
  > 系統需在調撥完成確認後，自動更新車輛主檔：
  > - 新增欄位 `transfer_freight_cost`（調撥運費）
  > - 重新計算 `total_cost` = 原成本 + 調撥運費
  > - 通知業務主管：「VIN XXXXXX 調撥運費已計入成本，建議售價需重新評估」

  **調撥運費的財務科目對照：**

  | 承擔方式 | 借方科目 | 貸方科目 |
  |---------|---------|---------|
  | 經銷商B承擔 | 應收帳款（對B） | 運輸費用收入 |
  | 經銷商A承擔 | 應收帳款（對A） | 運輸費用收入 |
  | 海德生承擔 | 調撥運輸費用（營業費用） | 應付帳款（對運輸商） |
  | 計入車輛成本 | 整車在庫成本（流動資產） | 應付帳款（對運輸商） |

  **調撥運費欄位（新增至調撥單）：**

  | 欄位 | 說明 |
  |------|------|
  | 運輸商 | 下拉選擇或手動填入 |
  | 預估運費 | 申請時填入 |
  | 實際運費 | 調撥完成後確認（可與預估不同） |
  | 費用承擔方式 | 見上表，申請時選定 |
  | 運輸憑證號 | 運輸商開立的單據號碼 |
  | 費用確認狀態 | `PENDING`（待確認）/ `CONFIRMED`（已確認）/ `INVOICED`（已開票） |

**調撥單欄位：**

| 欄位 | 說明 |
|------|------|
| 調撥單號 | 系統自動產生 |
| 調撥類型 | 寄倉 / 所有權轉移 / 調撥 |
| 來源倉庫 | |
| 目的倉庫 | |
| 車輛列表 | 可多台 |
| 預計調撥日期 | |
| 核准人 | 主管 |
| 調撥原因 | |

### 5.3 中古車整備工單（PD-UC）

#### 頁面：`SA_中古車整備工單.html`（新頁面，或在現有工單系統新增業務類型）

**與新車PDI的差異：**

新車PDI（`PD-IN`）是標準化的29項出廠前確認，中古車整備（`PD-UC`）則根據車況差異會有不同的整備深度。

**中古車整備分級：**

| 整備等級 | 代碼 | 說明 |
|---------|------|------|
| 基礎整備 | `RECON-A` | 清潔、基本安全檢查，適用A級車況 |
| 標準整備 | `RECON-B` | 含零件更換（輪胎/電瓶/耗材），適用B級車況 |
| 深度整備 | `RECON-C` | 含機械維修，適用C級車況 |
| 翻新整備 | `RECON-D` | 含鈑金烤漆，適用D級車況或CPO認證車 |

**中古車整備工單必填清單（PD-UC checklist）：**

**A. 安全系統（必查）**
- [ ] 前後煞車系統功能（含碟盤厚度）
- [ ] ABS系統作動確認
- [ ] 輪胎胎壓、胎紋深度（低於1.6mm必換）
- [ ] 燈光系統：頭燈/方向燈/尾燈/煞車燈
- [ ] 儀表板所有警示燈確認（無未處理故障碼）
- [ ] 油門/離合器作動確認
- [ ] 車架結構目視檢查（無彎曲/裂縫）

**B. 機械系統**
- [ ] 引擎啟動與怠速確認
- [ ] 傳動系統（鏈條張力/皮帶/軸傳動）
- [ ] 引擎機油液面與品質（依里程決定是否換油）
- [ ] 冷卻液液面（水冷車型）
- [ ] 煞車油/離合器油液面
- [ ] 電瓶電壓測試（<12.4V建議更換）
- [ ] 空氣濾清器狀態
- [ ] 火星塞狀態（依里程）

**C. 外觀與電裝**
- [ ] 外觀瑕疵記錄與拍照存檔（每個瑕疵點位照片）
- [ ] 坐墊狀態
- [ ] 後視鏡/手把/腳踏完整性
- [ ] USB/充電插座功能
- [ ] 藍牙/多媒體系統功能

**D. 文件確認**
- [ ] VIN碼與行照一致性確認
- [ ] 里程表讀數存檔
- [ ] 重大事故歷史再確認（對比外觀實際狀況）

**E. 估價確認**
- [ ] 各整備項目實際工時記錄
- [ ] 實際更換零件清單與成本
- [ ] 整備完成後車況等級評定（可能與收購時不同）

### 5.4 整備費用計入中古車成本

**整備工單（PD-UC）完成核准後，系統執行：**

1. 讀取工單所有工時費用與零件費用
2. 寫入車輛主檔：
   - `recon_cost` = 整備工單費用合計
   - `total_cost` 重新計算：`收購價格 + recon_cost`
3. 如為 RECON-D（翻新整備），額外處理：
   - 鈑金烤漆費用以獨立科目記錄（`bodywork_cost`）
   - 仍計入 `total_cost`
4. 車輛狀態從 `PENDING_RECON` 更新為 `AVAILABLE`
5. CPO等級可由主管在此時確認並設定
6. 通知業務主管：「VIN：XXXXXX 整備完成，現可銷售，整備後成本：NT$ XXX,XXX」

**費用科目對照（中古車整備）：**

| 費用項目 | 借方科目 | 貸方科目 |
|---------|---------|---------|
| 整備工時費 | 中古車在庫成本（流動資產） | 售後部門內部服務收入 |
| 整備零件費 | 中古車在庫成本（流動資產） | 零件庫存（流動資產） |
| 鈑金烤漆費 | 中古車在庫成本（流動資產） | 外部供應商應付帳款 |

### 5.6 中古車調撥管理（含運費處理）

中古車的調撥邏輯與新車大致相同，但有一個關鍵差異：**調撥可能發生在整備完成之前（待整備階段）或整備完成之後（可售階段）**，兩種時機的費用歸屬與業務影響完全不同，系統必須分開處理。

---

#### 情境一：整備前調撥（`PENDING_RECON` 狀態）

**發生情境：**
中古車收購後，海德生或某經銷商認為「這台車應該送到另一個有整備能力的據點」再進行整備，所以在整備工單建立後、執行前就發起調撥。

**典型例子：**
- 某台中古車在經銷商C收購，但C沒有整備設備，需調至海德生主倉整備
- 某台高損傷車（RECON-D）需送至有鈑金烤漆能力的合作廠

**系統處理流程：**
1. 發起調撥申請前，系統檢查車輛是否有未完成的整備工單
2. 若有：**暫停整備工單**（狀態改為 `PAUSED`），等調撥完成後在目標據點恢復執行
3. 調撥期間車輛狀態：`IN_TRANSIT_TRANSFER`
4. 到達目標據點確認後：
   - 整備工單狀態恢復為 `PENDING`（待分派）
   - 工單的執行地點更新為目標據點
   - 通知目標據點售後主管

**此階段調撥運費的特殊性：**
> 整備前調撥的運費，**幾乎必然應該計入車輛成本（`FREIGHT-VEHICLE`）**，因為整備尚未完成，車輛總成本還沒有定案，這筆運費是「讓車輛到達可整備地點」的必要支出，屬於整備成本的前置費用。

**費用欄位：**

| 欄位 | 說明 |
|------|------|
| 調撥運費 | 實際運輸費用 |
| 費用承擔方式 | 預設建議 `FREIGHT-VEHICLE`（計入整車成本），可由主管改選其他方式 |
| 若選計入成本 | 寫入車輛主檔 `transfer_freight_cost`，重新計算 `total_cost` |
| 整備完成通知 | 調撥+整備全部完成後，一次性通知業務主管最終整車成本 |

---

#### 情境二：整備後調撥（`AVAILABLE` 狀態）

**發生情境：**
中古車整備完成、已進入可售庫存，但此時因為庫存調配或客戶需求，需從一個據點移到另一個據點。

**典型例子：**
- 某台已整備完成的中古車在海德生主倉，某經銷商有客戶詢問，申請調撥
- 某台已定價上架的中古車需移到展示中心展示

**此階段調撥運費的選擇更靈活，需在調撥申請時明確選定：**

| 費用承擔方式 | 代碼 | 說明 | 對整車成本的影響 |
|------------|------|------|--------------|
| 由申請方（接收據點/經銷商）承擔 | `FREIGHT-B` | 費用計入申請方應付帳款 | 不影響整車成本 |
| 由調出方承擔 | `FREIGHT-A` | 費用計入調出方應付帳款 | 不影響整車成本 |
| 海德生承擔 | `FREIGHT-IMP` | 計入海德生營業費用 | 不影響整車成本 |
| 計入車輛成本 | `FREIGHT-VEHICLE` | 整車成本增加，建議售價需重新評估 | **影響整車成本與毛利** |

> ⚠️ **若選擇計入車輛成本（整備後調撥）：**
> 系統應顯示警告提示：
> ```
> ⚠️ 注意：此台車已完成定價
> 目前建議售價：NT$ XXX,XXX
> 整車成本原為：NT$ XXX,XXX
> 加入調撥運費後：NT$ XXX,XXX（+NT$ X,XXX）
> 目前毛利將從 XX% 降至 XX%
> 是否確認將調撥運費計入整車成本？
> ```
> 需主管層級確認才能執行。

---

#### 中古車調撥的通用欄位（調撥單新增欄位）

現有調撥單欄位基礎上，**中古車調撥需額外填寫**：

| 欄位 | 說明 |
|------|------|
| 調撥時車輛狀態 | 系統自動帶入：`待整備` / `可售` |

| 運輸商 | 下拉選擇 / 手動填入 |
| 預估運費 | 申請時填入 |
| 實際運費 | 調撥完成後確認（可與預估不同，差異超過20%需主管確認） |
| 費用承擔方式 | 見各情境說明 |
| 費用確認狀態 | `PENDING` / `CONFIRMED` / `INVOICED` |
| 運輸憑證號 | 運輸商開立的單據號碼 |
| 到達確認照片 | 到達目標據點後上傳（確認外觀無運輸損傷） |

| 計入車輛成本（整備前） | 中古車在庫成本（流動資產） | 應付帳款（對運輸商） | 整備完成後再計算最終成本 |
| 計入車輛成本（整備後） | 中古車在庫成本（流動資產） | 應付帳款（對運輸商） | 需主管核准，同步更新建議售價 |

### 5.5 CPO / DPO / CO 分級定義

| 等級 | 全名 | 適用條件 | 整備要求 |
|------|------|---------|---------|
| CPO | Certified Pre-Owned（原廠認證中古） | Indian品牌、年份≤3年、里程≤15,000km、無重大事故 | RECON-B以上，原廠檢核表100%通過 |
| DPO | Dealer Pre-Owned（經銷商認證中古） | Indian品牌、年份≤5年、里程≤30,000km | RECON-B以上，海德生內部標準 |
| CO | Certified Other（認證其他品牌） | 非Indian品牌但通過海德生整備認證 | RECON-B以上，海德生內部標準 |
| 無認證 | — | 不符合上述條件 | 基礎整備即可販售，需向客戶說明 |

**CPO認證在RS03B看板顯示特殊badge，售價可加成。**

## 九、頁面間資料流與API串接規格

### 9.1 關鍵資料流

```
INV01採購訂單
    ↓ 提交採購
車輛主檔（狀態：IN_TRANSIT）× N台
    ↓ INV02到港確認
車輛主檔（狀態：PENDING_PDI）
    ↓ 自動觸發
售後PDI工單（PD-IN，費用歸屬：VEHICLE_COST）
    ↓ 技師執行SA_PDI工單執行.html
工單費用寫回車輛主檔（pdi_labor_cost + pdi_parts_cost）
    ↓ 工單完成核准
車輛主檔（狀態：AVAILABLE，total_cost更新）
    ↓
RS03A新車庫存看板（即時顯示）
    ↓ 業務建立訂單
車輛主檔（狀態：RESERVED）
    ↓ 交車確認
車輛主檔（狀態：SOLD）
    ↓ 財務出庫
保固啟動申請
```

```
RS06中古車評估鑑價（置換）/ INV05中古車收購申請（直購）
    ↓ 收購確認
車輛主檔（vehicle_type=USED，狀態：PENDING_RECON）
    ↓ 自動觸發
售後整備工單（PD-UC，費用歸屬：VEHICLE_COST）
    ↓ 技師執行SA_中古車整備工單.html
工單費用寫回車輛主檔（recon_cost）

```
