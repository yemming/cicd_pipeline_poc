## C-25 LINE 逐客戶推播

**現況**
- `sendCampaignAction` 目前只推「**摘要**」到開發群組 `C4d5c08…`（commit 26812e5），**非逐客戶**。
- `customers` **無 `line_user_id`** 欄位。
- Notification Hub 走 Messaging API 直推（非 Zapier）。

**缺口三層**：(1) customers 加 `line_user_id`；(2) 客戶 OA 綁定（拿到 userId 並對應到 customer）；(3) `sendCampaignAction` 改 query 受眾 → 逐人 / multicast。

**綁定方式決策**
| 案 | 做法 | 備註 |
|---|---|---|
| 加好友 webhook + 綁定碼 | 客戶加 OA 好友 → follow event 拿 userId → 引導輸入綁定碼/手機對應 customer | 自動化高、要 webhook endpoint + 綁定 UX |
| LINE Login (OAuth) | 客戶在綁定頁 OAuth 授權 → 拿 userId 寫回 customer | 需綁定頁，客戶要點連結 |
| 後台手動 / 匯入 | RS 手動填 / TSV 匯入 line_user_id | 最快上線、覆蓋率低 |

**建議**：分兩階段。
- **Phase 1**：加 `customers.line_user_id` 欄位 + `sendCampaignAction` 支援「對**已有 line_user_id** 的受眾 multicast」（LINE multicast API 上限 500/批，分批）。綁定先靠後台手動 / 匯入。
- **Phase 2**：OA 加好友 webhook 自動綁定（綁定碼流程）。

**⚠️ 風險**：對真實客戶群發 LINE 是 **outward-facing 不可逆**。上線前必先只對「自己的測試 userId」驗，正式群發要明確 gate + 你點頭。

**待拍板**
1. 綁定走哪案（webhook+綁定碼 / OAuth / 後台手動）？
2. 是否先做 Phase 1（multicast 給已綁定者）即可滿足 B 型展示？
