## 2. A 類：去重（完全重複節點）

indian 庫存模組發現約 25 對**同 href、同名、皆 active** 的重複節點（sidebar 每頁顯示兩遍）。例：

```
/parts/setup/items            ×2   商品基礎資料
/parts/setup/pricing          ×2   門市定價
/parts/setup/compatibility    ×2   適配設定
/parts/alerts/dashboard       ×2   告警儀表板（另有 2 筆 /parts/operations/balance 已 off）
/parts/purchase/orders        ×2   商品採購
/parts/receipt/po-grn         ×2   採購入庫
... （入庫/出庫/盤點/作業/保固 多處成對）
```

**處置**：每組同 href 保留一筆（保留 `created_at` 最早或 active 的那筆），其餘 `is_active=false`（或刪除，待定）。
**待調查**（task #5）：是哪次 seed 造成 double，是否 ducati / 其他模組也有，避免修完復發。

> 🙋 **決策點 A**：重複節點要 **軟刪（is_active=false 留紀錄）** 還是 **硬刪（DELETE）**？建議軟刪，安全可回。

## 5. D 類：逐頁對映（高風險，需 Russell 提供對照表）

規範每模組逐頁列了 HTML 檔名 + 角色可見 + 應用場景，但 prod 是 React 路由。要 1:1 對齊必須有一張 **「規範 HTML 頁 ↔ prod 路由」對照表**，否則無法安全判斷：

1. 規範某頁在 prod 是哪個路由（同義改名：規範「中古車評估鑑價」= 現「置換評估」？「報價與成交訂單」= 現「報價簽訂」？「交車管理」= 現「交車流程」？）
2. prod 有、規範沒有的頁（如 銷售「潛客跟進」「訂單中心」「工作台首頁」「員工九宮格」「KPI目標/HABC」）→ 關掉還是保留？
3. 規範有、prod 缺的頁 → 是缺頁待建，還是只是名字沒對上？
4. 每頁的角色可見（規範詳列）→ 目前 nav_nodes 沒有 per-role 欄位（只有 is_admin_only），要不要做角色級可見是另一個工程。

> 🙋 **決策點 D**：請 Russell 針對五模組提供「規範頁 → prod 路由」對照（或授權我先產一份「我方推測對照表」回給 Russell 勾選）。**這步沒對照表前不動任何頁的去留。**
