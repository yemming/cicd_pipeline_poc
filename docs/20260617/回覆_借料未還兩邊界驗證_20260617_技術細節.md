## 核心修正：判定邏輯從「工單層級」改成「逐件量化」

前一版用 `未結案 || 有pending退料` 這種工單層級的粗判，無法回答「還有幾件在外、哪件拖最久」，
正是裁示三點出的模糊來源。本輪改為**逐件計算**（`getTlOutstandingLoanStatus`）：

```
某零件「未還量」 = 已出庫量 − 已確認回庫量(confirmed) − 已處置量(charge/absorb/transfer)
  · 已出庫：橋接 work_order 的 completed 領料單 stock_issue_lines.qty_issued
  · 已確認回庫：parts_return_requests(source_ro_id=TL, status='confirmed').qty_confirmed
  · 已處置：tl-close 對該零件選 charge_customer / absorb / transfer（已被會計或轉單消化）
  · pending / overdue 退料「不」扣除 —— B-01：倉管實體點收前，零件還在外面
```

- chip：「借料未還 N 項（最久 D 天）」，顏色由**最久未還件**決定（最保守、讓人先看到最該擔心那筆）。
- detail 逐件明細：每件列出「已借 D 天（分級色）· 品名 ×數量 ·（出庫時間）」，並標示「另有 X 筆退料待倉管點收」。

## 邊界情境一：分批出庫，天數起算是否誤導

### 驗證結論：現行為「原子出庫」，分批不可達 → 不存在天數混算的誤導

我方追查倉管領料流程的可達性（附 code 佐證）：

- 「待領料工單」清單 `listPendingPartsWorkorders`（src/domain/issues.ts:752-756）：工單一旦有 completed
  領料單即 **return null 排除**。
- 「綁定 RO 工單」新增領料清單：前端 `new-repair-pick-form.tsx:351` 對 `already_picked` **硬過濾**。
- 直接打 `?ro=` 繞路無效（new/page.tsx 不讀 searchParams）；後端 previewRepairPick 也不支援「扣已領、領剩餘」。

**結論**：一張 TL 工單的零件**只能一次領料、原子出庫**，所有零件共用同一出庫時間。因此「最早一筆
出庫時間起算」與「每件各自起算」在現行流程下**結果必然相同**，不可能出現「老件與新件被算成同一天數」
的誤導——因為根本沒有「分不同日期出庫」這條路。

### 但仍做到逐件清晰（不只給一個籠統數字）

即便如此，為符合裁示三「倉管一眼看懂哪些拖久、哪些剛出庫」的標準、且未來若領料規則調整也不誤導，
detail 的**逐件明細**會把每件的「已借天數 + 出庫時間」分開列、tier 取最久件決定顏色。

真實 e2e（全程 UI、無塞值）：TL-IN-260617-003 借 2 件（傳動#001、煞車#002），一次領料後
detail 顯示：

> 截圖 `shots-boundary/D1_after-pick-2items.png`：chip「借料未還 2 項（最久 0 天）」+ 明細兩件
> 各列「已借 0 天 · 出庫 2026-06-17 16:53」——同一出庫時間、逐件攤開，零模糊。

> 若日後真的開放分批出庫，逐件明細會各自顯示不同出庫時間與天數、chip 仍以最久件警示——
> 邏輯已為此預留，不會把新件舊件混為一談。

### 直球回答裁示三的兩個提問

**1. chip 是否持續正確顯示「借料未還」？**
是。狀態②是關鍵證據：工單**已關單**、且已建 2 筆退料申請，但因倉管**尚未實體點收**，chip 仍顯示
「借料未還 2 項」，明細並標「另有 2 筆退料待倉管點收」（見 D2 截圖）。**不會因為「有退料動作」就
顯示沒事。** 狀態③確認 1 件後，chip 準確降為「1 項」、明細只剩未還的煞車#002——降的是「已確認
回庫」那件，不是把警示整個關掉。

**2. 天數是否會因為有退料動作被誤判成風險降低、甚至「沒事」？**
不會。三個狀態天數一律「最久 0 天」（從出庫日算，不受退料動作影響）。`outstanding` 只看「逐件未還量
是否 > 0」，pending 退料**不扣未還量**（B-01）。**只要還有任一件未經倉管實體點收回庫，chip 一定持續
顯示「借料未還」、絕不會出現「沒事」或不顯示。**

### 為什麼這樣設計（對齊 B-01）

「未還」的對齊點是**倉管實體點收回庫**那一刻，不是技師喊還、也不是工單結案。pending 退料代表
「申請退、倉管還沒點收」——零件物理上還沒回到貨架，就算還在外面。這正是 B-01：回庫也要倉管
點頭才算數，顯示邏輯不替倉管把警示提前關掉。
