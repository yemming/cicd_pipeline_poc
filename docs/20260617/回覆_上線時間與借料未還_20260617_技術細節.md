## 要求三：「借料未還」可視狀態 — 門檻建議、UI 呈現、實作

### 設計理解（先講為什麼，再講做什麼）

我方接受裁示：不用中性的「退料在途」，改用帶催促語氣的「**借料未還**」——一句給倉管/主管看了會警覺的警語（「還沒還，是不是該問一下？」）。並依「系統主動把風險翻成警語、讓對的人在對的時間看到」的原則落地。

「借料未還」的判定 = **TL 零件已經由倉管 repair-pick 正式出庫，且尚未全部歸還回庫**
（TL 尚未結案，或仍有退料待倉管確認）。天數從**實際出庫日**（最早一筆領料過帳時間）起算
——那才是「借了幾天」，與 due_by（當天下班，另一個 badge）語意不同。

### 門檻建議（依現有 UI 色階規範）

Russell 指定「3 天內正常 / 超過 7 天警示」。我方建議在中段補一階 amber「注意」做漸進升級，
形成三階（若要收斂回兩階，拿掉 amber 即可，我方依裁示調整）：

| 分級 | 天數 | 語氣 | UI 色票（沿用現有 overdue/due chip 慣例） |
|------|------|------|------|
| 資訊 | ≤ 3 天 | 純資訊提示 | 資訊藍 `bg #EAF4FB / text #185FA5 / border #BBD9F2` |
| 注意 | 4 – 7 天 | 開始注意 | 警告 amber `bg #FDF3E3 / text #854F0B / border #F0C97E` |
| 警示 | > 7 天 | 主管關注（加 ⚠） | 危險紅 `bg #FDECEA / text #CC0000 / border #F5AEAD` |

門檻常數抽成可調整（`LOAN_OUTSTANDING_INFO_MAX=3`、`LOAN_OUTSTANDING_WARNING_MIN=7`），
Russell 確認後可一行改。

### UI 呈現與位置

- **位置**：TL 工單 detail 頁標題列的 badge 區，緊接既有「今日 HH:MM 截止」badge。
  SA 與主管一開工單就看到。文字「借料未還 N 天」，>7 天加「⚠」。
- 截圖（真實工單 TL-IN-260617-001，剛出庫）：`shots-real/09_borrowed-not-returned-closeup.png`
  —— badge 列顯示「今日 18:00 截止」（紅）＋「借料未還 0 天」（藍，資訊階）。

> 為何先做 TL detail 這個 surface：這是「已出庫但還沒結案」這個風險窗最直接、改動最小、
> 主管最常開的地方。倉管端的退料待確認（return-in）已有自己的到期/逾期紅黃分級
> （`renderDueBy`），涵蓋「結案後等倉管點收」那段窗。若 Russell 希望把「借料未還」同樣
> 鋪到 return-in 列或工單列表，我方可在下一輪追加（屬展示層擴充，邏輯共用同一套門檻 helper）。
