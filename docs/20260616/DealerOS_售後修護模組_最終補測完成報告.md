### 🚨 核心衝突（最重要，請 Russell 裁示）

您的業務規則：**「同車保養(MN)和維修(RP)必須分開開兩張獨立工單、可並存」**。

但現行程式（`confirmRepairOrderAction`）對「同車已有任一張進行中/維修中/待結帳的 open 工單」是**硬擋、無 override、且不分業務類型**——MN 施工中時，連開 RP 都會被擋（反之亦然）。實測已證實：MN-CP-260616-T02 維修中時，嘗試開 RP 工單直接被擋下、RP 未建成。

**所以您要的「同車 MN + RP 兩張並存」現行程式做不到。** 警示橫幅文字本身也寫「送出系統將阻擋重複開單」。這是**程式的『一車一單』規則 vs 您的『MN/RP 分單並存』規則直接衝突**。需要產品決策 + 程式改動（例如硬擋邏輯加入 prefix_p1 例外：MN 與 RP 視為不衝突、允許並存），才能支援此業務場景。**本輪如實測出衝突，未自行改規格。**

- **技師追加項目 server error**：在測試工單上點「確認追加」→ 後端 500、addon 未寫入。最可能是技師角色缺「追加項目」權限導致 requirePermission 拋例外（過往有「權限定義了但沒 seed」的雷），或類型欄未帶。**建議 dev 用權限完整的技師帳號 + UI 正常建的工單複測確認是真 bug 還是環境/權限問題。**
