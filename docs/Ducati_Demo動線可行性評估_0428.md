## 一、緣起

依您 4/28 對「銷售動線・3 分鐘」與「維修動線・5 分鐘」兩段 demo 口白的反饋，校準我方原本偏向「IT 功能展示」的腳本方向，重新依您所定義的**完整業務情境流程**（個人視角＋主管/店長視角雙軌）盤點可行性，並具體列出尚需補充的規格資料。

## 二、您的校準抓到了什麼

我方原始腳本以「點按鈕、看自動化、看推播」為主軸，本質上是 **IT 功能展示**。您指出客戶（經銷商老闆、銷售顧問、SA）每天經歷的是**完整業務情境**，IT 技術展示只是次要——這個校準至為關鍵，列為後續設計的最高指導原則。

具體而言，校準補齊了三項原本遺漏的核心內容：

1. **個人視角與主管/店長視角為兩條獨立動線**，並非同一動線的不同切換。客戶 demo 時可能於不同對象面前展示不同段落。
2. **離店後維繫**（銷售側 B/C 級客戶）與**離廠後增項追回**（售後側）才是真正的銷售/服務功夫；當場成交、當場修完僅為少數情境。
3. **週五全組複盤**是經銷商老闆每週固定動作；缺此段，主管/店長視角即不成立。

## 四、結論

**核心結論：能走完全程，但需分兩層回答。**

1. **個人視角**：銷售約 60% 可實作，售後約 75% 可實作。剩餘部分皆為您原本標示為「保留設計」的模組（試駕、報價、訂車、領料、收銀），原本即未列入本期範圍。
2. **主管/店長視角**：目前僅銷售漏斗看板可用，**整個週五複盤流程全缺**，為本次反饋後最大補強重點。

## 五、需請 Russell 補充提供的資料清單

為使 demo 走完全程，建議補充以下規格。形式不拘——HTML 原型、Excel、或文字描述皆可，毋須改寫為系統圖。

### 銷售側

- 報價單格式（欄位、Ducati 車款定價表範例）
- 訂車契約格式（欄位、條款、訂金規則）
- 試駕流程規格（駕照拍攝、試駕車預約、保險條款）
- 離店後維繫節奏表（A/B/C 級各自聯繫頻率、話術重點）
- 週五複盤報表格式（銷售組）

### 售後側

- 車間派工規格（車位／技師／工序分配規則）
- 庫房領料出料流程（含欠料處理）
- 結帳收銀 UI 規格（現金／信用卡／轉帳／發票開立）
- 車間即時監看看板規格（車位狀態、技師打卡進度、工時統計）
- 週五複盤報表格式（售服組＋技師組兩個維度）

### 共用

- 老客戶 seed 資料 5–10 筆（demo 故事用，不需真實資料）
- 員工角色設定（陳大為＝銷售、林志強＝SA、其他主管/店長角色）

## 六、建議的執行階段

考量您不必一次補齊所有規格，建議將 demo 拆為兩階段：

### 第一階段（本期）

- 範圍：個人視角兩條動線
- 完成度：銷售約 60%、售後約 75%
- 處理方式：保留模組畫面以「Phase 2 上線」標籤帶過，不影響 demo 流暢
- 預計工時：約 5–6 個工作天

### 第二階段（下期）

- 範圍：主管/店長視角的週五複盤動線
- 待您補齊複盤報表格式與目標調整流程後再啟動
- 此階段是經銷商老闆的決策痛點，IP 價值最高
