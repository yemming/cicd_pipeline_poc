# Part A：售後修護模組 — 業界概念說明

## 一、為什麼重機業需要現代化售後管理？

### 傳統做法的痛點

台灣重機售後服務長期依賴：
- 紙本工單，技師手寫作業項目
- 報價靠記憶或查紙本價目表，無法即時給客戶準確報價
- 零件缺料靠口頭通知，流程斷點多
- 客戶取車靠SA打電話，無標準化通知流程
- 保固舊件隨意放置，DUCATI廠方稽核時找不到

這些問題導致：客戶等待時間長、費用不透明、糾紛多、技師效率低、保固費用難追回。

## 二、核心概念解說

### 2-1. 工單業務類型與付款性質

重機售後工單依業務性質分為六種類型，每種對應不同的費用歸屬：

| 業務類型 | 代碼 | 付款性質 | 費用歸屬 |
|---------|------|---------|---------|
| 定期保養 | MN | CP（客付）| 客戶 |
| 一般維修 | RP | CP（客付）| 客戶 |
| 保固維修 | WC | WR（保固）| 原廠廠方 |
| 事故維修 | AC | CP/IN | 客戶或保險 |
| PDI整備 | PD | IN（內部）| 整車成本 |
| 返工工單 | RP-FR | FR（本店）| 門店自負 |

**重要規則：**
- MN（保養）和RP（維修）若同一台車同時需要，**必須開立兩張獨立工單**，不可合併
- PD整備工單費用計入整車成本，不向客戶收費
- 返工（RP-FR）：30天內同一問題再次回廠，費用由門店承擔，不向客戶收費

---

### 2-2. Quick Quote 快速報價查詢的設計邏輯

**為什麼需要獨立的Quick Quote頁面？**

SA接待客戶時，需要在客戶面前即時查詢保養套餐費用並報價。若塞在預檢單Tab2的側邊欄，平板操作空間不足；若讓SA跳到庫存管理模組查詢，超出SA的操作範圍。

**Quick Quote的三種結果設計：**
```
✅ 車主同意 → 報價資料自動帶入 04_預檢單_RO串接 Tab4 → SA無需重填
⏸ 暫存     → 預檢單Tab4顯示「待車主確認」→ SA可繼續其他接待
❌ 拒絕     → 記錄原因寫入人車檔案「待處理項目」→ 下次回廠自動提醒SA
```

這個設計確保Quick Quote不只是查詢工具，而是與完整工單流程串接的業務閉環。

---

### 2-3. 電子簽名的法律意義

售後流程中有**兩次**客戶簽名，各有不同的法律意義：

| 簽名時機 | 位置 | 法律意義 |
|---------|------|---------|
| **第一次**（預檢完成）| 04_預檢單_SA環檢 Tab5 / 04_預檢單_RO串接 Tab5 | 車況交接確認：客戶確認車輛進廠時的外觀損傷記錄，簽名後SA不可再修改車況描述 |
| **第二次**（結帳前）| 08_結帳收款 Step2 | 費用確認授權：客戶確認費用明細，簽名後費用鎖定不可修改，防止事後改單糾紛 |

⚠️ 兩次簽名均已改為真實canvas元件，簽名圖像需儲存至後端並與工單ID綁定。

---

### 2-4. 工單進度條與通知節點

**為什麼需要進度條？**

客戶送修後最常問的是「我的車修好了嗎？什麼時候可以來取？」若SA只能靠走去問技師，效率極低且容易遺漏。

**工單六個狀態：**
```
待派工 → 施工中 → 追加待確認 → 竣工複檢 → 待結帳 → 已關閉
```

**通知機制的設計原則（重要）：**
系統在每個狀態轉換點**提醒SA**，由SA人工決定是否通知客戶及通知方式（LINE/簡訊/電話）。系統**不自動外發**任何通知，確保SA掌握溝通節奏，避免未確認情況下系統自動通知客戶引發誤解。

---

### 2-5. 追加項目閉環的完整流程

業界最容易產生糾紛的環節是「追加項目」——技師發現額外問題，客戶不知情就多收費。DealerOS的設計確保每個追加都有完整授權記錄：

```
技師發現問題
    ↓ 記錄在 04_追加項目記錄.html
SA收到系統提醒（系統內通知）
    ↓ SA選擇通知方式（LINE/電話/簡訊）聯繫客戶
客戶決定
    ↓
同意 → 庫存預留備料 → 倉管收到備料提示 → 出庫 → 費用計入工單
暫緩 → 工單標記「待料」，D+3/D+10系統提醒主管追蹤
拒絕 → 記錄拒絕原因 → 寫入人車檔案待處理項目 → 下次回廠自動提醒
```

**安全疑慮項目（緊急）**：系統強制要求SA記錄通知方式與時間，不可跳過。

---

### 2-6. 委託取車授權

客戶無法親自取車時，非車主本人代取的授權記錄是門店的法律保護：

```
取車人確認 → 委託取車
    ↓
填寫：取車人姓名 + 身份證/手機末4碼
選擇授權方式：現場電話向車主確認 / LINE截圖 / 系統提前登記
委託人電子簽名（代車主）
```

此流程整合在 08_結帳收款.html 的 Step 1B，不需獨立新增頁面。

---

### 2-7. 下次保養提醒的業務價值

**業界數據**：主動提醒客戶回廠的門店，客戶回廠率比不提醒的高出40-60%（NADA 2025報告）。

DealerOS在結帳完成後自動計算下次保養里程：
- 6000km保養完成 → 建議下次 +6000km
- 10000km保養完成 → 建議下次 +6000km
- 20000km大保養 → 建議下次 +6000km（下個小保養）

計算結果寫入人車檔案，同步至CRM01B保養到期快篩清單，CRM主管可主動電訪提醒。

---

### 2-8. 服務套餐標準化的重要性

**沒有標準化套餐的問題：**
同一台Panigale V2的10000km保養，不同SA報出的價格可能差NT$500-2000，客戶回家一查發現差距，直接影響信任感。

**07B服務套餐設定解決的問題：**
- 主管預先設定標準套餐，SA只需選套餐即可報價
- DUCATI採全球統一標準工時（LU），費率由門店設定
- Indian Motorcycle可依車型自訂工時和費率
- 促銷套餐有有效期，過期自動停用，SA不會看到已過期的套餐

---

### 2-9. PDI整備工單與新車上架流程

**新車從到港到可售的完整狀態機：**
```
RS_INV02 到港確認（掃描VIN）
    ↓ 自動建立 PDI 工單
02_PDI工單執行（技師勾選29項清單）
    ↓ 主管雙簽核准
費用寫回整車成本，車輛狀態 → AVAILABLE
    ↓
RS03A 新車庫存看板出現此車（可售狀態）
```

⚠️ PDI完成前，車輛**不得**出現在RS03A可售庫存中。這是整個新車業務最重要的流程節點。
