### 1. `10_預警告警_庫存水位設定.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 06_預警告警 / 10_預警告估_庫存水位設定.html`
**操作類型：** 🔄 完整替換

**修改原因：**
原版只有讓倉管手動填寫最小庫存/再訂購點/最大庫存三個數字，無任何計算輔助。倉管若不了解再訂購點的業界計算邏輯，填入的數字毫無意義，告警系統形同虛設。

**新增功能：**

#### 1-1. 再訂購點計算輔助器（➕插入到頁面標題後）
```
插入位置：page header（.ph）之後
功能：
  - 輸入：日均消耗量（個/天）+ 供應商前置天數 + 安全庫存量
  - 公式：再訂購點 = 日均消耗量 × 前置天數 + 安全庫存量
  - 輸出：即時計算建議再訂購點，可一鍵套用至選定料號
  - Phase 1（新系統）：手動輸入估計值
  - Phase 2（6個月後）：依歷史出庫數據自動建議
  - 附PDC截單時間說明（DUCATI原廠前置天數=1）
```
📌 **行業背景：** 重機零件不同於一般零售，DUCATI等原廠零件有固定PDC（Parts Distribution Center）系統，下午5點前送單可隔日上午到貨，前置天數極短。這是設定再訂購點時的重要參數。
🔗 後端：`PATCH /api/inventory/reorder-point`

#### 1-2. 可用庫存計算公式說明（➕插入）
```
插入位置：計算輔助器之後
內容說明：
  可用庫存 = 帳面庫存 - RO工單預留量 - 調撥在途出庫量 + 採購在途入庫量
  ⚠️ 重要：SA在04B快速報價查詢看到的庫存狀態必須是「可用庫存」而非帳面庫存
```
🔗 後端：`GET /api/inventory?sku=XXXX&include_reserved=true`

### 2. `04_採購管理_商品採購.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 02_採購管理 / 04_採購管理_商品採購.html`
**操作類型：** 🔄 完整替換

**修改原因：**
業界標準中，原廠PDC有明確的截單時間（DUCATI：下午5點）。這對「今日缺料、明日必須施工」的緊急場景至關重要，但現有頁面完全沒有截單時間提示，倉管可能錯過截單時間導致工單延誤。

**新增功能：**

#### 2-1. PDC截單時間倒計時（➕插入到頁面標題後）
```
插入位置：page header（.ph）之後
功能：
  - 即時倒計時顯示距DUCATI原廠PDC截單（17:00）的剩餘時間
  - 不到1小時：紅色警示
  - 截單後：顯示「已截單」並說明緊急費用
  - 顯示三個供應商的截單時間：DUCATI（17:00）/ 台灣代理（15:00）/ 一般供應商（依合約）
  - 「緊急送單」按鈕：一鍵提交緊急採購單
```
📌 **行業背景：** DUCATI台灣PDC系統（通過正式代理商）可在下午5點前送單，隔日上午到貨。此機制對處理「當日工單發現缺料」的場景至關重要，是業界重機DMS的標準功能。
🔗 後端：`POST /api/purchase-orders/urgent`

### 3. `05_入庫管理_採購入庫.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 03_入出庫管理 / 05_入庫管理_採購入庫.html`
**操作類型：** 🔄 完整替換

**修改原因：**
業界標準「三核對」驗收（料號/數量/外觀）是庫存準確性的基礎。現有頁面無驗收差異（短收/損壞）的處理路徑，倉管遇到問題時不知如何操作，且無憑證記錄。這也是供應商績效評分的數據來源。

**新增功能：**

#### 3-1. 驗收差異處理區塊（➕插入到頁面標題後）
```
插入位置：page header（.ph）之後
三個功能入口：
  📉 數量短收 → 開啟差異記錄Modal（填料號/差異數量/說明）→ 觸發採購退貨流程
  🔴 損壞拒收 → 開啟差異記錄Modal（附拍照上傳）→ 建立拒收憑證通知供應商
  📋 批次匯入 → 上傳原廠到貨清單CSV，系統自動比對採購單標示差異
```
📌 **行業背景：** DUCATI原廠零件每次到貨附有原廠發貨清單（Delivery Note），批次匯入比對可大幅減少人工核對時間。差異記錄是未來供應商績效評分的依據。
⚠️ 測試前必須：差異記錄是庫存準確性和供應商管理的基礎
🔗 後端：`POST /api/receiving/discrepancy`；`POST /api/receiving/batch-import`；`POST /api/receiving/diff-photo`

### 4. `06_出庫管理_維修領料.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 03_入出庫管理 / 06_出庫管理_維修領料.html`
**操作類型：** 🔄 完整替換

**修改原因：**
現有設計的流程斷點：SA確認追加項目後，需倉管主動去04_追加項目記錄查看，或SA手動開新分頁跳轉。業界標準是「追加確認後倉管端自動出現提示」。另外缺少工單號快速帶入功能，技師到庫房後仍需倉管手動查找。

**新增功能：**

#### 4-1. 待備料工單提示橫幅（➕插入到頁面標題後）
```
插入位置：page header（.ph）之後
功能：
  - 頁面載入時自動顯示「共N張工單需要準備零件」
  - 每張工單顯示：工單號、車主姓名、車款、車牌、需求零件清單、優先級
  - 緊急工單紅色標示
  - 「備料 →」按鈕直接進入對應工單出庫流程
  - 「重新整理」按鈕
```
⚠️ 測試前必須：這是追加項目確認→庫房備料的關鍵流程串接點

#### 4-2. 工單號快速帶入（➕插入）
```
插入位置：待備料橫幅之後
功能：
  - 輸入框支援鍵盤輸入或條碼掃描槍掃描工單號
  - 按Enter或點擊按鈕 → 自動帶出該工單所有需求零件清單
  - 倉管逐項確認後執行出庫，不需手動搜尋工單
```
🔗 後端：`GET /api/workorders?status=pending_parts`；`GET /api/workorders/{id}/parts-needed`

### 5. `08_盤點管理_盤點處理.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 05_盤點管理 / 08_盤點管理_盤點處理.html`
**操作類型：** 🔄 完整替換

**修改原因：**
原版「條碼掃描模式」按鈕只顯示Toast。業界標準（CDK Lightspeed、DMS Systems）是使用平板/手機相機掃描零件包裝條碼即時更新盤點數字，大幅提升盤點效率並減少手動輸入錯誤。

**新增功能：**

#### 5-1. 相機條碼掃描（🔄替換假的掃描按鈕）
```
替換位置：原有「📱 條碼掃描模式」按鈕
功能：
  - 調用裝置相機（getUserMedia API，後置鏡頭優先）
  - 顯示相機預覽畫面（video元件）
  - 每500ms截圖分析（實際部署需整合BarcodeDetector API或ZXing函式庫）
  - 識別成功後自動更新對應料號的盤點數量
  - 支援：69碼條碼、QR Code、備件代碼
  - 相機關閉時停止串流（釋放資源）
  - 無相機設備時自動降級為鍵盤輸入模式
```
📌 **行業背景：** CDK Lightspeed在2023年推出的Mobile Service Check-In功能即採用此設計。重機零件盤點通常一年進行1-4次（ABC分類：A類月盤），相機掃描可將盤點時間縮短40-60%。
🔗 後端：`POST /api/stocktake/scan`（接收料號+數量，即時更新盤點記錄）

### 6. `11_保固索賠_暫存倉設定.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 07_保固索賠 / 11_保固索賠_暫存倉設定.html`
**操作類型：** 🔄 完整替換

**修改原因：**
原版只有倉庫層級設定，缺少「庫位」層級。DUCATI原廠保固稽核要求能快速找到特定舊件，沒有庫位設定時舊件一多就找不到。另外缺少「從RO工單觸發舊件入庫」的接收流程，倉管只能手動新增。

**新增功能：**

#### 6-1. 暫存倉儲位設定（➕插入）
```
插入位置：原有暫存倉列表之前
功能：
  - 設定到庫位層級（WC-A01 ~ WC-A10等）
  - 依業務類型分區：WC-保固件區 / AC-事故件區
  - 各庫位目前存放數量即時顯示
  - 新增/編輯庫位設定
```
📌 **行業背景：** DUCATI原廠保固稽核（每1-2年一次）要求經銷商能在1小時內找出特定保固索賠對應的舊件。沒有精確到庫位的設定，舊件找不到可能導致保固費用被拒付。

#### 6-2. RO工單觸發舊件入庫流程（➕插入）
```
插入位置：儲位設定之後
功能：
  - 顯示「竣工複檢已通過，待確認儲位」的工單列表
  - 倉管選擇庫位後點「確認入庫」
  - 連帶更新保固暫存倉庫存 + 索賠申請狀態→「待申報」
```
🔗 後端：`GET /api/warranty-parts?status=pending_storage`；`PATCH /api/warranty-parts/{id}/storage-location`；`PUT /api/warranty-warehouse-locations/{id}`

### 7. `02_基礎設定_供應商資訊.html` 🔄 替換

**目錄位置：** `04_庫存管理 / 01_基礎設定 / 02_基礎設定_供應商資訊.html`
**操作類型：** 🔄 完整替換

**修改原因：**
業界所有主流DMS（CDK Lightspeed、DealerClick、BiT）均強調供應商績效評分是採購決策的核心。現有頁面只有基本聯絡資料，倉管無從判斷哪個供應商在緊急補貨時最可靠。

**新增功能：**

#### 7-1. 供應商績效看板（➕插入到頁面標題後）
```
插入位置：page header（.ph）之後
欄位：交貨準時率 / 平均前置天數 / 短收率 / 退貨率 / 綜合評分 / 採購建議
評分等級：A+優先 / A優良 / B一般 / C需改善
數據來源：從採購入庫記錄自動計算（上線初期為示意假資料）
```
📌 **行業背景：** 重機零件有原廠件（DUCATI/Indian PDC）和副廠件兩個採購渠道。緊急補貨時需要快速判斷哪個供應商能最快到貨且品質穩定。績效評分將入庫差異記錄（參見第3點）自動統計為量化指標。
🔗 後端：`GET /api/suppliers/{id}/performance`

### 8. `10B_告警儀表板_v1.html` 🆕 新增頁面

**目錄位置：** `04_庫存管理 / 06_預警告警 / 10B_告警儀表板_v1.html`
**操作類型：** 🆕 全新頁面，放入 06_預警告警 目錄（與 10_預警告警系列並列）

**新增原因：**
業界最高優先的庫存管理視圖。倉管每日工作開始時需要「一頁掌握所有需要立即處理的庫存問題」，現有系統分散在水位設定、採購管理、盤點等多個頁面，倉管必須逐一查看才能了解全貌，效率極低。

**功能說明：**

#### KPI 總覽（4個數字卡）
```
🔴 低於最小庫存（N個料號）→ 需今日PDC截單前補貨
🟡 低於再訂購點（N個料號）→ 建議本週內採購
⏳ 工單待備料（N張）→ SA已確認，倉管需準備出庫
📅 批號30天內到期（N件）→ 需優先出庫或促銷
```

#### 5個分Tab詳細清單
```
Tab 0：🔴 緊急（低於最小庫存）
  - 顯示料號/庫位/目前庫存/缺口數量
  - 「緊急補貨」按鈕（直接發緊急採購單）
  - 「跨店查詢」按鈕（查看其他門店庫存）
  - 「批次緊急補貨」按鈕（全選一次送單）

Tab 1：🟡 預警（低於再訂購點）
  - 顯示料號/目前庫存/再訂購點/差距
  - 「建立採購單」按鈕
  - 「批次建立採購單」按鈕

Tab 2：⏳ 待備料工單
  - 顯示工單號/車主/車款/需求零件清單/優先級
  - 「前往備料」按鈕（跳轉至維修領料頁）
  - 資料來源：04_追加項目記錄確認後自動觸發

Tab 3：📅 批號到期
  - 顯示料號/批號/到期天數/剩餘數量
  - 「優先出庫」按鈕
  - 「促銷處理」按鈕
  - FIFO原則提醒說明

Tab 4：📦 採購逾期
  - 顯示採購單號/逾期天數/是否影響工單
  - 「催單」按鈕
  - 「取消改向」按鈕
  - 供應商績效影響說明
```

#### 標題欄 PDC 截單倒計時
```
即時顯示：當前時間 ｜ 距PDC截單剩餘時間
讓倉管一進頁面即知道今日還能否送原廠緊急單
```

🔗 後端 API 清單：
- `GET /api/inventory/alerts?type=below_min`
- `GET /api/inventory/alerts?type=below_reorder`
- `GET /api/workorders?status=pending_parts`
- `GET /api/inventory/batch-expiry?days=30`
- `GET /api/purchase-orders?status=overdue`
- `POST /api/purchase-orders/urgent`
- `POST /api/purchase-orders/batch`
- `GET /api/inventory?sku={sku}&all_stores=true`
