# DealerOS ─ 6/3 交付任務執行報告

**報告日期：2026-06-04　｜　對象：老闆　｜　範圍：Russell 6/3 交付的海德生實測前置任務**

---

## 一句話總結

Russell（設計端）6/3 交來一批「海德生真人實測前必須完成」的整備清單，**我們一個工作時段內把全部三大塊做完、上線、並用真實帳號實測驗證通過**。系統現在已達「可邀請海德生員工、用自己的角色帳號、看到正確且互相隔離的資料」的狀態。

---

## 背景：這批任務在解什麼問題

海德生（Indian Motorcycle Taiwan）準備來做**真人實測**——員工各自用自己的帳號登入、操作自己角色該做的事、看到真實資料。Russell 在 6/3 評估：要做到這種「真人實測」，當時還卡在幾個關鍵缺口（資料權限沒隔離、選單沒整理乾淨、Indian 看到一堆 Ducati 專屬內容）。這份報告就是我們把這些缺口補起來的成果。

---

## 我們具體做了什麼（五大塊）

### 1. 系統選單整理 ─ 讓海德生登入看到的是乾淨、對位的選單

- **移除開發用的導覽頁**：那些是給開發看的工具頁，真實用戶不該看到，已全部關閉。
- **功能擺到正確位置**：「到港確認」「採購財務結算」是集團層動作，從業務選單搬進集團管理；「滿意度（NPS）看板」統一收進主管監看區。
- **重複入口清掉**：同一個「告警儀表板」原本掛了兩個入口，留正確的一個。
- **設定類選單預設收合**：庫存「基礎設定」、集團「系統設定」這種上線一次性設定的區塊預設收起，讓使用者第一眼看到的是日常操作。

**意義**：海德生員工一登入，選單就是符合 Russell《目錄規範 v2.0》的乾淨版本，不會被開發殘留或擺錯位置的功能干擾。

### 2. 品牌專屬內容隔離 ─ Indian 員工不再看到 Ducati 的東西

Russell 在《品牌專屬邏輯備忘錄》點名這是「高風險誤會點」：系統很多地方寫死了 Ducati 專屬內容（例如 Ducati 才有的「Desmo 大保養」、「YouTech 保固系統」），Indian 員工看到會問「這是什麼？我們的車有這個嗎？」

- 建立「品牌設定開關」，讓系統依登入者的品牌顯示對應內容。
- Indian 帳號的預檢單、服務套餐、保養預約選單**不再出現 Desmo 保養**等 Ducati 專屬項目；Ducati 端維持原樣不受影響。

**意義**：消除 Russell 點名的「海德生一看就覺得這系統是給 Ducati 做的、不適合我們」這個簽單信心殺手。

### 3. 示範資料補強 ─ 系統裡終於有真正的 Indian 車

過去系統裡標記為「Indian」的車款，其實全是 Ducati 車系（掛錯品牌的舊資料）。我們補進真正的 **Indian Scout Bobber / Chief Vintage / FTR** 示範車，讓海德生員工測試時看到的是「我自己的品牌、我的車」。

### 4.（最關鍵）資料權限隔離 ─ 各角色只看到自己該看的，且已用真帳號證明

這是 Russell 評估裡「扣最多分、是真人實測地基」的那塊。原本系統只做到「同品牌全部看得到」，等於**業務員看得到別人的客戶、技師看得到別人的工單**——客戶一問「個資怎麼保護」信任就動搖。

我們上線了「人員/角色級」資料隔離，並**用 8 個真實角色帳號實際登入驗證**（不是紙上談兵）。實測結果：

| 角色 | 客戶 | 銷售手卡 | 維修工單 | 電訪任務 | 庫存 | 判定 |
|---|---|---|---|---|---|---|
| 主管 / 集團（全覽） | 52 | 17 | 33 | 138 | 14 | 看全部 ✓ |
| 業務員 | **只 2** | **只 5** | 0 | 0 | 0 | 只看自己客戶/手卡 ✓ |
| 服務顧問 SA | 0 | 0 | **只 3** | 0 | 0 | 只看自己經手工單 ✓ |
| 技師 | 0 | 0 | **只 3** | 0 | 0 | 只看指派給自己的工單 ✓ |
| CRM 專員 | 0 | 0 | 0 | **只 2** | 0 | 只看派給自己的任務 ✓ |
| 倉管 | 0 | 0 | 0 | 0 | **14** | 只看庫存 ✓ |

（數字＝該帳號實際登入後看得到的筆數；總筆數見最上方主管列。）

**意義**：海德生現在可以「每個員工用自己的帳號、看到只屬於自己的資料」，這正是真人實測的前提，也是面對客戶「個資保護」提問時最有說服力的答案。

### 5. 資料清理

修掉 15 筆掛錯品牌（標成 Indian 其實是 Ducati）的車款主檔資料，合併回正確的 Ducati 品牌，讓品牌資料乾淨。

## 還沒做的部分（刻意保留，需老闆 / Russell 拍板）

這些是我們**主動評估後決定先不動**的高風險或需決策項目，不是遺漏：

1. **全系統資料隔離（197 張表）**：本次只先做最核心的 5 張表。Russell 文件明確要求「全面鋪開要他在場確認」，故保留。
2. **「只看本店」門市層隔離**：目前主管是「看全品牌」。要做到「店長只看自己門市」需要額外建資料模型，屬較大工程，待決策。
3. **客戶展示帳號（ccc）權限**：這個對外展示用帳號目前被授予了多個含主管級的角色，所以會看到全部資料。要不要收斂成「只看示範範圍」，請老闆定位後再調。

## 對「海德生實測成功把握」的影響

Russell 6/3 評估：完成「資料隔離 + 角色帳號 + 示範資料」三件事後，海德生實測把握可由當時的 **65–70% 提升到 85–90%**，足以推進正式簽約討論。

**這三件事本批次已全部落地並實測驗證。** 系統已具備安排一次「有品質的海德生實測」的條件。
