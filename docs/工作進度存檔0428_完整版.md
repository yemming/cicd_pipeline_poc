### DMS 演進脈絡
| 版本 | 年代 | 特徵 |
|------|------|------|
| DMS 1.x | 1992~2005 | 單機/LAN架構，原始程式語言，速度慢 |
| DMS 2.x | 2006~2015 | 分散式架構，導入客戶為中心概念 |
| DMS 3.x | 2016~2019 | 社群化潛客互動，客戶畫像，多IT技術整合 |
| DMS 4.0 | 2020+ | 車機一體，AI數智決策，行銷創新，組織變革 |

### 數據應用三層次
- **DI（數據化智慧）**：量化數據定義/收集/重組/備份，管理效率提升
- **BI（商業化智慧）**：訂單/庫存/交易/消費習性，即時報表決策
- **AI（人工智慧）**：自動識別判斷，發掘深層資訊

### CLV 客戶生命週期價值（三維度）
1. **客戶維持時間（CM）**：維持長期關係，建立高CM率
2. **客戶份額（CS）**：企業產品占客戶總消費的比重
3. **客戶規模（Scope）**：現有客戶數量與新客開發

### ARPU 各業務期毛利點
- **新車業務期**：新車毛利、貸款毛利、加裝毛利、新保毛利、換購毛利
- **售後業務期**：機修毛利、鈑噴毛利、養護與精品毛利
- **中古車業務期**：續保或再換購毛利

### 展廳銷售動線 KPI（8個環節）
1. 電話接待：客流量、來電邀約到店率、線索分配
2. 展廳接待：展廳留檔率
3. 需求諮詢：判定客戶級別
4. 產品介紹：動線與流程優化
5. 試乘試駕：試乘試駕率、試駕成交率
6. 交易洽談：報價率、訂單轉化率、成交率、金融/保險滲透率、銷售毛利
7. 車輛交付：庫存周轉率、交車滿意度
8. 售後跟蹤：銷售滿意度

### 系統核心痛點（現況）
- 60% 工作花在資料整合、轉移、核對及即時更正
- 40% 工作花在人工統計數字及輸入報表系統

### 提案系統核心亮點
- **業務財務一體化**：覆蓋線索管理、庫存管理及交易管理
- **監控管理精準化**：即時監控庫存、銷售、毛利等 KPI

## 二、系統架構（完整版 v3）

### 前段｜銷售流程
1. **CRM 客戶管理** — 來客紀錄、首次/回訪識別、來源追蹤、電訪問卷、聯絡紀錄
2. **電子手卡（v7）** — 來客識別、客戶資料、初步分析、接待結果（詳見第四節）
3. **預約與到店** — 電話/線上預約、提醒通知、試乘安排、業務指派排班
4. **車輛庫存管理** — 新車在途/在庫、中古車 CPO/DPO/PO、庫齡分析、跨店調撥（詳見第三節）
5. **金融與保險服務** — 金融機構/產品、協作報價、保險機構/方案/出單管理、金融保險銷售日報
6. **置換與轉介** — 舊車估價、轉介來源追蹤、老客戶回購、中古車置換銜接

### PDI 跨部門協作節點
- 新車成交 或 中古車售出 → 系統自動建立 PDI 工單
- 派工至售後服務部門技師執行
- 新車：原廠標準清單；中古車：安全件/耗材/CPO-DPO認證項目
- 缺失追蹤（補件/重檢流程）
- 完成後通知銷售主管與銷售顧問準備交車

### 後段｜售後服務流程
1. **維修管理** — 維修項目/工時設定、套餐管理、預約管理（預約單及看板）
   - 售後維修流程：預檢單 → 工單製作 → 零件調整 → 派工調度 → 技師打卡 → 完工/竣工檢查 → 提交結算 → 收款/發票 → 出門單
2. **車間管理** — 派工調度、技師打卡分配、完工檢查（工種品管）、竣工檢查（最終品管/含返工單）
3. **商品管理（配件）** — 零配件主檔/價格/適配關係、採購管理（補貨/緊急訂貨/退貨）、入庫/出庫/庫存/盤點管理
4. **倉庫管理** — 倉區/庫區/庫位設置、配件擺放定位維護、供應商資訊與採購合同
5. **人車檔案與保固** — 客戶檔案、車輛檔案、維修履歷查詢、CPO/DPO 保固追蹤、到期通知
6. **售後財務管理** — 收款管理（預收/工單/退款）、對帳管理（應收/應付）、核銷管理、發票管理、出門單
7. **客訴與滿意度** — 客訴追蹤、NPS 評分、電訪問卷（首次離店/成交/休眠/準戰敗）、改善行動
8. **數位溝通與通知** — Line/簡訊推播、保養到期提醒、保固到期通知、行銷活動推播
9. **資料報表** — 財務/利潤報表、進銷存台帳、庫齡分析、工時統計、工位佔用統計
   - 移動端支援：SA移動端（預檢/環車）、車間移動端（完工/竣工，iPad）、倉庫移動端（盤點，iPad）

### 共用基礎模組
- **系統設定與權限** — 組織/門店/職務權限、審批管理、車型設定、選單管理、任務調度
- **報表與分析看板** — 銷售漏斗看板、業績/庫存/毛利報表、跨部門策略表
- **多門市管理** — 跨店庫存調撥、集團層級監看、商務政策統一管控
- **客戶自助入口** — 線上預約/查車/維修、個人訂單查詢、行銷活動瀏覽
- **銷售主管設定** — 人員排班、來店管道、系統參數/折扣權限、審批流設置

## 三、車輛庫存管理模組（詳細）

### 在途追蹤｜新車來源
- 原廠訂單（下單車型/數量、預計到港日期）
- 物流/報關/入庫（船期航班追蹤、報關狀態）
- 客訂車配對 → **到車通知銷售主管與銷售顧問**（不通知客戶）

### 在途追蹤｜中古車調撥
- 調撥申請（來源門市確認、車輛狀態核對）
- 運送與交接（運送時程、到店驗收）
- 調撥費用分攤（跨店成本紀錄）

### 新車庫存
- 車型與規格（年式/車色/配備/建議售價）
- 展示車/促銷（試乘車里程、原廠優惠方案）
- PDI 出廠前檢查 → 已移至跨部門節點

### 中古車庫存（CPO / DPO / PO 三級）
- CPO：原廠認證、完整保固
- DPO：第三方檢驗、部分保固
- PO：收購估價、風險標記
- 車輛履歷查驗（維修歷程/事故紀錄/里程核實/定價比較）

### 庫存總量即時看板
**公式：在途數量（新車在途＋調撥在途）＋ 在庫數量（新車＋中古）－ 預訂鎖定 ＝ 可銷售總量**

### 共用庫存功能
- 多角度照片/影片、官網/App 自動同步
- 庫齡分析與周轉率、在庫/洽談/已售狀態
- 新車 vs 中古車毛利比較、跨門市庫存調撥紀錄
- 庫存預警（低於安全庫存自動通知主管）
- 車輛鎖定管理（鎖定後銷售顧問不可銷售）

### 手卡區塊結構（由上至下）
1. **Header** — 手卡標題、手卡編號（自動產生，格式：RC-YYYYMMDD-HHMM）
2. **接待資訊** — 接待銷售下拉、到店日期、到店時間、自動切換紀錄
3. **來客識別** — 四欄橫列網格（首次/老客戶介紹/來電預約/指定接待人員）、條件顯示再次進店（本月再次/再次<2個月/再次>3個月）、來店管道下拉（主管設定）、老客戶智慧提示
4. **客戶資料** — 平板攝影採集、姓名、性別、陪同、電話、Line ID（狀態＋方式）
5. **現有車輛資料** — 品牌、車款、顏色、手排/自排、配備（低/中/高）、車齡、里程
6. **初步分析** — 購買意向車種（新車/中古，可複選）、購買類型（首/換/增/重購）、換購展開（置換時機＋估價服務）、意向車型（新車車型＋顏色 / 中古車型＋是否在庫，常駐並排）、購買時機（本月/次月/季後/年後/未定）、考慮競品（品牌/車型/價位，可新增多筆）、付款方式（全款/貸款/租賃）、客戶級別 HABC
7. **試乘試駕** — 選「是」展開跳轉提示框（保留設計）＋暫用欄位（駕照拍攝橫幅、試駕車款、開始/結束時間、自動計算時長）
8. **接待結果** — 報價（是/否→跳轉報價單）、訂車（是/否→跳轉訂車契約）、交車（是/否→跳轉交車流程）、退訂（直接輸入訂單編號→跳轉退訂流程）、其他情況描述、備註
9. **在店時間紀錄** — 到店/離店、自動計算在店時長
10. **Footer** — 清除重填、儲存手卡

### 客戶級別 HABC 定義

| 級別 | 名稱 | 定義 | 系統建議邏輯 |
|------|------|------|------------|
| H | 高度意願 | 當月內購買，且完成試乘試駕 | — |
| A | 中度意願 | 1~2個月內決定，已完成試乘試駕 | 維繫期間尚未試駕 → 建議降為 B 級 |
| B | 低度意願 | 3~6個月才決定，尚未試乘試駕 | 願意再次來店試駕 → 建議升為 A 級 |
| C | 保留意願 | 長時間考慮，未試駕，聯絡3次以上未表態（非戰敗，非購他牌） | — |

## 八、重要設計決策紀錄

| 決策 | 原因 |
|------|------|
| 客訂車到車通知業務主管與顧問，不通知客戶 | 由銷售顧問主動聯繫客戶，確保服務品質 |
| PDI 獨立為跨部門節點，不屬於庫存模組 | PDI 由銷售觸發，售後技師執行，涉及跨部門 |
| PDI 同時適用新車與中古車 | 兩者售出前均需技師出廠前檢查 |
| Line ID 取得狀態移除「未詢問」 | 培訓政策：接待銷售必然詢問，不設逃避選項 |
| 換手接待改由下拉選單直接切換 | 培訓應變方法更簡單，無須額外按鈕 |
| 中古車在途追蹤 = 跨店調撥 | 經銷商間調車時同樣需要在途狀態追蹤 |
| 意向車型新車/中古車兩格常駐顯示 | 來客可能同時考慮新車與中古車，兩格均需填寫 |
| 退訂無是/否，直接輸入訂單編號 | 退訂是確定性動作，不存在「否」的情境 |
| 漏斗圖不顯示流失率 | 視覺精簡，重點放在各層數量與百分比 |
| 漏斗圖移除視角說明字樣 | 由系統模組位置決定，手卡本身不需標示 |

## 十一、提案報告背景知識（供 Claude AI 設計新模組時參照）

> 萃取自原始提案報告 v1，是理解整個系統設計邏輯的關鍵背景。

### DMS 演進脈絡
| 版本 | 年代 | 特徵 |
|------|------|------|
| DMS 1.x | 1992~2005 | 單機/LAN架構，原始程式語言，速度慢 |
| DMS 2.x | 2006~2015 | 分散式架構，導入客戶為中心概念 |
| DMS 3.x | 2016~2019 | 社群化潛客互動，客戶畫像，多IT技術整合 |
| DMS 4.0 | 2020+ | 車機一體，AI數智決策，行銷創新，組織變革 |

### 數據應用三層次
- **DI（數據化智慧）**：量化數據定義/收集/重組/備份，管理效率提升
- **BI（商業化智慧）**：訂單/庫存/交易/消費習性，即時報表決策
- **AI（人工智慧）**：自動識別判斷，發掘深層資訊

### CLV 客戶生命週期價值（三維度）
1. **客戶維持時間（CM）**：維持長期關係，建立高CM率
2. **客戶份額（CS）**：企業產品占客戶總消費的比重
3. **客戶規模（Scope）**：現有客戶數量與新客開發

### ARPU 各業務期毛利點
- **新車業務期**：新車毛利、貸款毛利、加裝毛利、新保毛利、換購毛利
- **售後業務期**：機修毛利、鈑噴毛利、養護與精品毛利
- **中古車業務期**：續保或再換購毛利

### 展廳銷售動線 KPI（8個環節）
1. 電話接待：客流量、來電邀約到店率、線索分配
2. 展廳接待：展廳留檔率
3. 需求諮詢：判定客戶級別
4. 產品介紹：動線與流程優化
5. 試乘試駕：試乘試駕率、試駕成交率
6. 交易洽談：報價率、訂單轉化率、成交率、金融/保險滲透率、銷售毛利
7. 車輛交付：庫存周轉率、交車滿意度
8. 售後跟蹤：銷售滿意度

### 系統核心痛點（現況）
- 60% 工作花在資料整合、轉移、核對及即時更正
- 40% 工作花在人工統計數字及輸入報表系統
- 年銷 1000 台的經銷商需 4 個全職銷售行政處理報表
- 4 個廠家系統、3 個總部系統、4 個常用日報表並存

### 提案系統核心亮點
- **業務財務一體化**：覆蓋線索管理、庫存管理及交易管理
- **監控管理精準化**：即時監控庫存、銷售、毛利等 KPI
- **銷售漏斗管理**：篩選各階段客戶，識別潛在成交價值
- **跨地點跨時間**：不在店內也可完成銷售，突破時間限制

### 系統前台/中台/後台架構（Slide 28 概念）
- **前台（展示層）**：PC、PAD、APP、網頁、社群平台、汽車媒體網站
- **中台（業務層）**：線索集客、邀約、接待、跟進、交車、商務審批、CRM、金融、保險

- **對接系統**：DMS、ERP、財務系統、稅務系統、簡訊/電郵閘道、品牌廠家、政府官方

### 七、增項閉環管理（Russell 發明，今日完整定義）

#### 背景與價值
- 車主來店多只記得定期保養，SA預檢與技師深入檢查會發現更多商機
- 這些「建議/追加項目」被車主以任何理由拒絕後，若無流程管理，業務流失可高達維修保養實際營業額的 **30%**
- 同時引發車輛安全隱患，造成車主事後抱怨，CS 體驗失分

#### 完整閉環流程
```
預檢單第三關（技師建議項目）
    ↓ 每個項目標記：
    ├── ✅ 車主同意 → 寫入 RO 執行 → 增項明細記錄「成交」
    └── ⏸ 車主暫緩/拒絕 → 自動觸發「增項閉環」
                ↓
        系統建立「失銷追蹤案件」
        記錄：項目/金額/未修原因/安全等級
                ↓
        D+3（離廠後第3天）
        SA 致電：溫馨提示/建議預約
        記錄：接通/未接/回應結果
                ↓ 若未成交
        D+10（離廠後第10天）
        SA 二次聯繫：盡義務提醒
        記錄：接通/未接/回應/去向
                ↓
    ┌── 回廠預約 → 建立新 RO → 閉環成功
    ├── 可持續跟進 → 30天後再提醒
    └── 戰敗結束 → 售後主管簽核 → 進入 CS 體驗追蹤參考
```

#### 安全等級分類
| 等級 | 說明 | 系統行為 |
|------|------|---------|
| 🔴立即必修 | 危及行車安全 | 售後主管須親自介入，強制告知並留記錄 |
| 🟡近期建議 | 損耗明顯，建議儘快 | SA 正常追蹤 |
| 🟢一般建議 | 可延後但建議執行 | SA 正常追蹤 |

#### 事後聯繫責任分工
| 時間點 | 負責人 |
|--------|--------|
| D+3 | SA 本人 |
| D+10 | SA 本人＋售後主管知悉 |
| 🔴安全等級未修 | 售後主管親自介入 |
| 戰敗結束 | 售後主管簽核存檔 |

**注意：規模小，取消 CS 聯動，完全由售後內部（SA＋主管）負責**

#### 失銷追蹤看板 — 分層設計

**【個人層】**
- SA：自己的待聯繫清單（D+3/D+10）、自己的提報率/成交率/追回率
- 技師：自己的增項發現率、安全項目比例

**【整店層】**
- 售後主管：全店狀態/逾期警示/🔴安全等級戰敗清單/整店趨勢
- 零件庫房：缺料比例分析/價格因素分析/庫存建議清單

#### 零件庫房決策參考
| 分析維度 | 決策方向 |
|---------|---------|
| 缺料比例高的項目 | 提高安全庫存量 |
| 價格因素高頻拒絕 | 反映給代理商議價 |
| 提報多但成交少（非價格/缺料） | SA 話術訓練 |
| 特定季節高頻項目 | 季節性備料計畫 |

#### 核心統計指標
- **提報率** = 增項提報台次 ÷ 當月定保機修總台次
- **提報成交率** = 增項成交台次 ÷ 增項提報台次
- **追回率** = 事後聯繫成交數 ÷ 失銷總數
- **缺料比例** = 缺料數量 ÷ 上報數量
- **戰敗率** = 最終放棄追蹤數 ÷ 失銷總數
